# Pagenor 0.15.0 — local upstream adaptation milestone

Desktop development preview. The source quality gate passes all seven stages.
Installers are built and verified on GitHub for universal Mac, Windows x64/x86/ARM64
and Linux x86_64/ARM64. This is an unsigned/ad-hoc signed preview: Windows signing
and Mac notarization are not configured.

Thirty upstream source scopes improve editing, footnote search, table borders,
IDML style references, dialog controls, safe font/image handling, GPU limits and
command-line behavior. Indic pattern breaking is available for Telugu, Hindi,
Marathi, Bengali, Assamese, Gujarati, Punjabi, Odia, Tamil, Kannada and Malayalam.
Set the text's language in Character options; ordinary English text keeps its
existing hyphenation rules. Indic syllable breaks do not add visible hyphens.

Native Edit > Paste can embed clipboard bitmaps or copied image files. An ordinary
text caret inserts one inline object; an empty selected frame receives the image,
otherwise a new frame is placed on the current page. This is one undo step and
embedded bytes survive native save/reopen. Stored image resolution determines
physical size, capped to 60% of page width and height. Reads are bounded, run off
the interface thread and are discarded if their target context changes.

Bitmap-only Ctrl/Cmd+V awaits a separate adaptation to the pinned frontend; use
Edit > Paste for bitmaps. Inline image insertion into tables or footnotes reports
unsupported without modifying their text. This release does not claim a full
Windows/Linux native runtime test or the affected Windows 10 user's performance
retest. The original 0.14.2 Windows update candidate files remain unchanged.

The source review, authors, immutable heads, regression results and remaining
queue are in [the adoption ledger](../upstream-adoption-20261120.md). Native
format capability remains 8. Pagenor branding and owner asset rights are retained.

## Validation

All seven workspace gates pass: **3,212 tests passed, zero failures, 7 existing ignores; twenty WASM packages**. Both Windows GNU and Linux GNU checks pass for eight shared libraries (doc, fonts, compose, images, format, render, IDML and PPTX). All 22 packaging contracts pass, including recovery publication gates. Four offscreen interface views were inspected. See the adoption ledger for evidence and platform limits.

## Changes retained from 0.14.2

- Windows installation has a success/Finish screen, desktop and Start menu shortcuts,
  and the same MSI upgrade identity for updating an existing 0.14.1 installation.
- Undo/redo history snapshots share memory until changed, reducing repeated panel work.
- Native live preflight checks run on a bounded background worker rather than during typing/painting.
- The byte-preserving PageMaker converter ships in Windows MSI and portable ZIP packages.
- Mac app and CLI packages now also contain a matching universal PageMaker converter,
  its corresponding MPL source and notices; no Homebrew or separate helper is required.

PageMaker import remains experimental. Original legacy fonts are required; automatic
Anu-to-Unicode conversion and identical PageMaker layout are not promised. The Mac
packaged-helper checks use isolated HOME/PATH, validate architecture/signature/system
library dependencies, and test three pages across two PAGE containers through native
save/reopen. Windows additionally checks fresh installation and upgrade preservation.
Save work and close Pagenor on Windows before running its matching MSI; do not
uninstall the old version first. The MSI is the updater. Windows 10 interactive
responsiveness still needs the affected user's retest.

Local release preparation additionally verifies the universal Mac helper on ARM64
and Intel, with only system-library dependencies. The owner's local PageMaker
sample retains 28 pages, 169 text frames and 110 shared stories through native
save/reopen; its source hash is unchanged and the publication is not uploaded.

The first hosted Mac packaging attempt caught a `lipo -verify_arch` invocation
error before artifacts were published. Architecture checks now verify one slice
per invocation, tested with the real universal helper and enforced by the Mac
packaging regression. A fresh release build uses the corrected source.

The first Windows install-verification attempt stopped before installation because
source checkout removed the previously downloaded artifact directory. Checkout
now precedes downloads, with a failing-before/passing-after regression. The
maintenance verifier can reuse the exact `release-windows-*` packages and checks
native architecture, version, PDF export, file associations, document icon and
notices as well as PageMaker, Finish UI and real 0.14.1 upgrade preservation.
This automation correction does not alter the already built application files.

The recovery publication path requires successful native Windows verification,
all twelve original build/source jobs, an ancestor source commit, and a diff
limited to release notes, workflow code and packaging tests. It rejects missing
or extra payloads and publishes all twenty installers/archives plus checksums
from that exact build, with the original binary commit as the release tag target.
