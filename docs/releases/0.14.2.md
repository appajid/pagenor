# Pagenor 0.14.2 — Windows setup and editing responsiveness

Local maintenance work, 20 November 2026. Validation is in progress; this is not
an announcement of a published release. Published 0.14.1 assets remain immutable.

- The MSI also acts as the update installer for registered Pagenor 0.14.1
  installations: major-upgrade detection replaces the old version. It creates a
  Pagenor desktop shortcut as well as the Start menu entry. Settings and saved
  documents are outside the installer payload; native upgrade/preservation testing
  is required before distributing this update.
- Windows interactive MSI setup now includes the normal welcome, installation
  progress, error/cancel and successful-completion/Finish screens. Silent /qn
  installation remains silent by design. The app is not forcibly launched.
- Windows MSI and portable ZIP packaging build and include the architecture-matched,
  statically linked PageMaker byte-v2 helper. It is selected beside Pagenor's own
  executable; no separate program or PATH configuration is needed. Packaging fails
  if the helper cannot be built. Explicit expert overrides retain precedence.
- Byte-v2 retains existing original-font byte transport, shared-story identities,
  raster recovery and all PAGE-container traversal. The helper remains a separate
  MPL process; source archives, modifications, build scripts and notices ship with it.
- Command rollback snapshots now share undo/redo history until it changes.
  Repainting toolbars and panels no longer copies every undo entry in every open
  document for each attribute query. Undo/redo and panic rollback remain protected.
- Live status-bar and panel preflight now use a bounded background worker on native
  Mac, Windows and Linux, instead of checking/composing the whole publication on
  the typing/paint thread. Reports are bound to the document snapshot and font
  generation. Stale results never describe a different document as error-free.
  The status shows Checking while work is pending. Explicit preflight.run remains
  synchronous; WASM keeps its snapshot cache.

PageMaker import remains experimental; original legacy fonts are still needed.
This does not promise identical layout, automatic Anu-to-Unicode conversion or
that every cause of editing/zoom slowness has been eliminated. No running Mac
session or installed app is replaced during development. Test results and Windows
native verification will be recorded after they complete.

Local validation completed: all seven gates pass, **3,169 tests, zero failures,
seven existing skips**, twenty WASM package checks. The opt-in owner-sample test
passes separately: 28 pages, 169 text frames and 110 shared stories survive native
save/reopen. The source hash is unchanged. The rebuilt static helper emits all
53 embedded raster placements without diagnostics. Eighteen package checks pass,
including nested-checkout patch application, source checksum rejection and MSI
payload/UI contracts. Two offscreen views were inspected: the overset issue is
shown, then switching to a fresh document shows No errors, without stale results.

Windows native installer/portable and 0.14.1 upgrade tests are pending. The Mac
installation remains 0.14.0 and its current session is not closed or replaced.

First Windows candidate run (90fee4a) compiled the Rust application/CLI, then
caught a Windows-only packaging failure: Git's newline conversion made the helper
patch fail against the LF upstream archives. The build now normalizes patch
line endings, overrides Git newline conversion only for the isolated apply calls,
and verifies the reverse patch. A CRLF/global-autocrlf regression covers this.
Helper compilation/architecture validation now precede the longer Rust build;
failed maintenance runs retain reusable Rust caches. Native retest pending.
